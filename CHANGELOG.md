## 2.0.0 (not yet published to npm)

2.0 runs the table from a terminal as well as over MCP, and keeps heads-down runs going on their own. Headlines: the duel mode and the `roundtable` CLI with per-seat models and provider judgment; CLI runtimes (Hermes, OpenClaw, Gemini CLI, Codex) as seats and as heads-down workers; the agents library and Casting Call; a credentials broker with MCP connectors for workers and seats; page checks and Docker dev-server previews; swarms; `roundtable serve` with private check-ins; `roundtable up` and `doctor`; a Docker image, a Claude Code plugin and an MCP registry listing; and the move to the Apache License 2.0. 1.1.0 was never published and ships with this release.

- **Provider judgment (#158, WS23).** Deterministic role, health, budget and usage-aware routing replaces the implicit provider default at the table and for heads-down review calls. MCP start tools accept `provider: "auto"`; seat reasons appear in terminal output, NDJSON, rooms and `routing` results. Explicit assignments remain authoritative. Providers with no known price stay eligible on an estimated cost that is counted against any budget, and routing history is scoped per endpoint. See [Provider judgment](docs/providers.md#provider-judgment).
- **CLI runtimes at the table (#189, #190).** Explicit runtime seats share provider dispatch in duels and collaborations, with built-in hermes, openclaw, gemini and codex profiles; strict user configuration, bounded process groups, env allowlists, preflight, usage accounting and `roundtable runtimes [--json]`. See [CLI runtimes](docs/runtimes.md).
- **Table CLI and env file.** `roundtable duel`, `debate`, `waffle`, `meeting` and `config` run at the table from a terminal, streaming turns and spend (`--json` for NDJSON). `roundtable config set env-file|agents-dir` saves settings in `~/.agent-roundtable/config.json`; `ROUNDTABLE_ENV_FILE` points to a private env file that supplies only allowed provider keys and model defaults, under an owner-only rule and an OpenAI-compatible pair rule. See [the table CLI](docs/table-cli.md) and [configuration](docs/configuration.md#saved-cli-settings-and-env-files).
- **Per-seat models.** `--seat agent=provider:model`, `--mix auto|cheap` and automatic preflight on the CLI; a `seats` argument on `start_collaboration` and `start_duel`; persona `provider`/`model` frontmatter.
- **Duel mode.** Two teams build competing artifacts for any brief, judges assess them against a rubric and the losing side files dissents. Teams of 1 to 4, judges 1 to 5, four artifact kinds (`web`, `code`, `diagram`, `text`), custom `criteria`, one or two rounds. Available from the terminal (with a live local room and `--replay` of saved archives) and as the `start_duel` tool. See [duel](docs/modes/duel.md) and the [demo script](docs/demo.md).
- **Duel to contract.** `propose_contract(from_session: "duel-<id>")` imports the winning decision and archived dissents, and by default drafts a task plan from the winning artifact (`draft_plan: false` opts out). `amend_contract(from_session: "duel-<id>")` adds a duel to an existing contract.
- **A duel as a meeting's focus.** `duel` and `duel_source` arguments on `start_meeting`, `start_local_meeting`, `start_collaboration` and `start_ultraplan`, and `--duel` / `--no-duel-source` on the CLI, give a session a size-capped brief of a saved duel to discuss.
- **Artifact-safe scrubbing.** Prototype and duel artifact content is scrubbed with credential-shaped rules only, so source identifiers stay intact while secrets are replaced.
- **Hardening.** Duel archives, seat models and configuration loading were tightened ([#173](https://github.com/ylove/agent-roundtable/pull/173)).
- **Documentation.** Every tool has its own reference section (43 orchestrator tools, 8 on worker servers), the CLI reference covers the table commands, and the environment variables are documented.

- **Connectors on every start tool, per-seat connectors, Ollama tools (#219, WS25c).** `connectors` now works on `start_meeting`, `start_ultraplan` and the casting call (`roundtable cast --connectors`) as well as the duel and collaboration tools; servers start once per session and close on end, stop and abort, and an unknown name is refused before anything starts. `--seat-connectors ada=figma,bob=jira+figma` and a `seat_connectors` map limit a seat to some of the session's connectors. Ollama seats can call tools through `/api/chat`. `start_local_meeting` is excluded (the Claude CLI owns its tools). Also moves the `connectors` property on the start tool schemas to `start_collaboration`, where the handler reads it. See [connectors at the table](docs/connectors.md#at-the-table).

- **Preview follow-ups (#220, WS26c).** A finished run's runner now stops that run's previews; duel prototype previews carry the duel id and the duel room shows only its own duel's; the forwarder gets its own per-preview network instead of the default bridge (removed with the preview and by the sweep); a plain `vite` dev script gets `--host 0.0.0.0` passed through, and a complex one without `--host` is refused with a clear message. See [previews](docs/previews.md).

- **Dev-server previews (#161, WS26b).** `roundtable preview start|list|stop` and the tools `start_preview`, `list_previews`, `stop_preview` run a task's or a duel prototype's dev server in a locked-down Docker container, published on `127.0.0.1` only (no tunnel, never `0.0.0.0`). The source is copied in, never mounted; the server sits on an internal network with no route out; dependencies install with scripts off through the npm-only egress proxy. The dashboard task page, the duel room and the serve index embed it in a sandboxed frame with a `frame-src` for exactly the running previews. See [previews](docs/previews.md).

- **MCP connectors for seats at the table (#160, WS25b).** Seats in duels, debates, waffles and meetings can call configured connectors as tools (`--connectors a,b`, or `connectors` on `start_duel` and `start_collaboration`): read-only tools by default, a per-connector `tools` list to allow more, broker credentials under the worker launcher's stripped environment, scrubbed and fenced results, a six-call cap per turn, and tool calling for Anthropic and OpenAI-compatible providers. See [connectors at the table](docs/connectors.md#at-the-table).

- **`roundtable up` and `doctor` (#149, WS20e).** One command for first-run setup (terminal only, every step skippable), a doctor that checks Node, git, provider keys by name, runtimes, Docker and Chrome, then starts the local service and prints the next steps. `roundtable --version`, `-v` and `version` print the version. Check-in text now masks only path-shaped text, so "50/50" and "and/or" stay readable. See [getting started](docs/getting-started.md#quick-start-roundtable-up).

- **Runtime adapters as heads-down workers (#191, WS22c).** `workers.driver: "runtime:<name>"` (or `execute(worker_driver: "runtime:<name>")`) runs hermes, openclaw, gemini or a configured runtime profile as a heads-down worker, opt-in with `ROUNDTABLE_ALLOW_RUNTIME_WORKERS=1`, under the Codex driver's controls: task worktree, allowlisted environment, leases enforced at submit, scrubbed output, priced usage. gemini gets the worker MCP server and its own `--sandbox`; runtimes without MCP are submitted for by the driver when they exit 0. See [runtimes as workers](docs/runtimes.md#as-heads-down-workers).

- **Long-running runs and private check-in (#163, WS28).** `roundtable serve`: durable local runner supervision, a read-only home index, private check-in channels, optional tailnet bind, and login service printouts. See [long-running runs](docs/long-running.md).

- **Distribution (#169, WS31).** A `Dockerfile` (digest-pinned base, non-root, CI build and smoke run, never pushed), a Claude Code plugin and marketplace entry, a `server.json` for the MCP registry with `mcpName`, and `scripts/sync-version.mjs` to keep their versions in step. Nothing is published by automation; see [distribution](docs/distribution.md).

- **License: Apache 2.0.** The project moves from the MIT License to the Apache License 2.0, with a `NOTICE` file.

- **Configured content filters (#204).** Automated host git calls refuse staging or writing working-tree content when a configured clean, smudge or process filter applies to a tracked or untracked non-ignored path. The error names the filter and one example path; filtered paths are unsupported in heads-down runs. Filter programs remain disabled, while read-only calls and filters attached to no listed path remain available. Repositories without configured filter programs skip the attribute scan.

- **Hardening follow-ups (#204, WS29b).** Guarded requests connect to approved addresses while retaining hostname TLS verification. Automated host git calls disable configured filters and diff programs and replace named merge drivers with a fixed Git text merge. Shell variables, including empty values, take precedence over the package `.env`. Completion tools refuse token limits outside 1–32768 or non-integers, and temperatures outside 0–2. Session tests pin persona and grounding containment and bounded reads.

## 1.1.0 (not published to npm; ships with 2.0.0)

Three features work together: dissents and tripwires carry concerns from planning into execution, postmortem mode reviews what happened and preserves lessons, and usage visibility shows their spend alongside the rest of the work.

- **Dissents and tripwires.** See the [user guide](docs/dissents.md) and [design](docs/design/dissents.md).
  - Contracts gain `dissents[]`: at most 16 concerns, each with a participant as author, provenance, a claim and a predicted failure (each limited to 500 characters). Dissents appear in the rendered contract and are included in both the contract and consent hashes.
  - `file_dissent` files or updates a draft concern, creating a new version that requires renewed consent; authenticated agents may file only their own concerns. An objector can explicitly resolve an `OBJECT` by consenting with a retained dissent. Every retained dissent needs a valid tripwire before freeze, or the orchestrator must explicitly excuse it with a reason. Frozen contracts use `amend_contract` and the existing consent or audited override path.
  - Debate and waffle house summaries extract challengers' and attackers' own `<DISSENT>` blocks; `propose_contract(from_session: …)` imports them with author and session provenance. Quoted, fenced or malformed blocks cannot file a concern. Unsigned ultraplan sessions also import archived `OBJECT` sign-offs as drafts. Imports need tripwires or explicit excusal before freeze.
  - Tripwires are non-executing predicates over recorded blackboard evidence: `check_failed`, `path_touched` or `task_state` (blocked or rejected). They never execute dissent text or grant filesystem access. `on_fire` chooses `notify`, `huddle` (default) or `pause_and_huddle`; every firing notifies the dissenter. A predicate fires once per affected task and generation; changing it through amendment re-arms it for new evidence.
  - In a micro-huddle, the dissenter opens and concludes the discussion and the participant whose work tripped the predicate answers. Both calls share a reserved allowance bounded by execution, task and requesting-agent budgets, and charge that requesting identity. Missing budget still permits notification and routes the concern to the orchestrator; disagreement, unavailable seats or exhaustion also use the escalation fallback.
  - `pause_and_huddle` holds only the affected task: worker tools refuse further work, the runner stops its worker, and submitted work cannot merge while held. Resolving or withdrawing an escalation releases only its own hold; other holds, dependencies and needs remain.
  - `score_dissent` lets the contract's orchestrator record `vindicated`, `refuted` or `untested`. Scores are advisory only: they never weight votes, change consent thresholds or affect routing. A firing does not automatically vindicate a prediction, and an unfired tripwire does not refute it.
  - The read-only Dissents dashboard page shows concerns, provenance, armed and fired tripwires, evidence, notification recipients, huddle outcomes and advisory scores. Firings and assessments are recorded as `dissent.tripwire_fired` and `dissent.scored`.

- **Postmortem mode.** See the [guide](docs/modes/postmortem.md) and [design](docs/design/postmortem.md).
  - Off by default and enabled per project only when the human asks for postmortem meetings or retrospectives. The orchestrator keeps a running draft of findings; enabled heads-down runs also record findings when testing sends a submission back or an integration check fails after a merge. Retries, merges and failures settle fixes, including recovery already present when a delayed scan records the finding.
  - After all fixes settle and affected tasks stop running, the agents that did the work meet the orchestrator at the table: waffle house when one agent is responsible for every finding, otherwise `collaborate`. The human has no seat, and the meeting excludes their chat, original prompt and confirmation. A draft with no findings closes without a meeting.
  - Meetings propose `fix`, `rule`, `persona_addendum`, `agent_rule`, `contract_rule` and `memory` artifacts. Only explicitly accepted artifacts take effect on conclude, each audited with its hash; persona addenda use the agent workshop's backup-first write path. Overlapping meetings cannot overwrite a held record, and conclusion retries recover publication or pending scoring audits without reapplying artifacts.
  - Postmortems review the run's dissents, including claims, predictions, tripwires, firing evidence and current assessments. Findings can propose evidence-backed `dissent_score` artifacts; explicit acceptance, project opt-in and the contract's orchestrator identity apply them through the same validated scoring path as `score_dissent`. Changed predictions or tripwire generations require a new review. Scores remain advisory and never become planning lessons.
  - Lessons are read before the next plan even when the mode is off: `propose_contract` returns `postmortem_lessons`, adds contract rules as `decisions` and flags misreadings as warnings; `start_ultraplan(repo_dir: …)` adds bounded lessons to planning context; heads-down task cards carry project and persona rules.
  - Private atomic writes keep records and lessons under `ROUNDTABLE_HOME/projects/<project_key>/`; drafts never held follow `ROUNDTABLE_SESSION_RETENTION_DAYS`. The dashboard gains a Postmortems page, `execution_status` reports the draft, and the watcher wakes with `postmortem_ready` and `postmortem`. While the runner and optional issue sync are alive, a concluded meeting also appears as one comment on the parent issue.

- **Usage visibility.** See the [usage guide](docs/usage.md).
  - See who spends what, on which platform, through the `usage` tool, `agent-roundtable usage [--json] [--watch]`, the dashboard Usage page and `agent-roundtable statusline`. The status line combines the host's reported figures with roundtable spend and the busiest agents, answers within about 150 ms and always exits 0.
  - Every token count and cost identifies its provenance: **measured**, **reported** or **estimated**. Mixed totals show the split, estimated spend stays labelled, and an unpriced model shows tokens and "no price" rather than `$0.00`. The Usage page has per-agent cards, platform totals, budget shares and spend sparklines; Overview gains a compact usage card.
  - Stop one agent with the dashboard's **Stop** button, `agent-roundtable stop <agent>`, `control_execution(action: "stop_agent")` or `usage(action: "stop")`. A heads-down worker keeps its work while its task is blocked and the orchestrator wakes to rework or write a handoff; stopping a participant at the table ends that session. `control_execution(action: "handoff")` and `usage(action: "handoff")` write a run's `HANDOFF.md` or `sessions/<id>.handoff.md`.
  - Dissent micro-huddle persona and driver calls appear in the ledger with dissent, execution, task, charged-requester, provider/model and cost provenance. Paid calls reserve estimated spend before dispatch; a usage report replaces its reservation by call id, so the call is never charged twice. Dispatched calls without usage retain estimated spend, including after failure, timeout or recovery; free local providers remain free.
  - Stop on either huddle participant or the affected worker settles reported usage, retains dispatched unreported allowance as estimated, releases unused allowance and routes the unresolved huddle to the orchestrator. Late reports settle the same entries without restarting the huddle. Stop and dissent holds are independent: resolving a dissent cannot resume a task with an unresolved Stop escalation, and Stop cannot release a dissent hold.
  - Run-backed postmortem calls charge each speaking persona with source `postmortem`, call and postmortem ids, and token/cost provenance. Spend is saved on success and failure, including a failed meeting whose draft remains available to retry. Standalone meetings use the per-persona table ledger; missing usage uses text-length estimates.
  - `budget.usage_recorded` carries provider and provenance, the blackboard tracks per-agent and per-model usage, and external workers can report spend with `post_update(kind: "usage")`. Sessions at the table keep a private ledger (`usage/table-YYYY-MM-DD.jsonl`) containing identities, numbers and provenance, without message text, subject to `ROUNDTABLE_SESSION_RETENTION_DAYS`.
  - Dashboard Stop requests require a per-start nonce, origin and site checks, no request body and rate limiting. Other dashboard routes remain read-only.

- **Tools, events and compatibility.**
  - Orchestrator tools increase from 37 to 42; worker tools from 7 to 8. The five additions are `file_dissent`, `score_dissent`, `postmortem`, `hold_postmortem` and `usage`; `file_dissent` is also exposed on worker servers.
  - CLI subcommands increase from 8 to 11: `statusline`, `usage` and `stop` are new. No arguments still starts the orchestrator MCP server. See the [CLI reference](docs/cli.md).
  - New events: `dissent.tripwire_fired`, `dissent.scored`, `postmortem.finding_recorded`, `postmortem.fix_updated`, `postmortem.started`, `postmortem.concluded`, `agent.stop_requested` and `agent.stopped`. Existing `contract.objection_resolved` supports `how: "dissented"`; `budget.usage_recorded` gains provenance and provider information, and `agent.exited` can report `stopped`.
  - `REDUCER_VERSION` is 10; older snapshots are discarded and the blackboard is rebuilt by replaying the event log.
  - New contract fields: `dissents` and `postmortem: {enabled}`. Existing contracts without dissents default to an empty list; postmortem mode requires project opt-in.
  - Node ≥ 22 remains required.

## 1.0.0

- Security fixes for 0.4.0 and earlier (upgrading is recommended):
  - Local meetings ran the `claude` CLI with the server's whole environment, including every provider key, with its default tools and with the working repository's own settings and hooks, and passed the prompt in argv where leading dashes could be read as flags. They now get an allowlisted environment, read-only tools, `--restricted` with repository hooks disabled, and the prompt on stdin.
  - A per-call `base_url` sent the OpenAI-compatible provider's configured key to whatever host it named. The key now goes only to the configured origin and any listed trusted origins, Untrusted URLs must use https (plain http only to loopback), cloud metadata addresses are always refused and private ones unless allowed, and credentialed requests never follow redirects.
  - Child processes inherited every variable loaded from `.env`. Each kind of child now gets an allowlisted environment, and worker MCP servers skip `.env` entirely.
- Heads-down execution: turn an agreed plan into a versioned contract with the human's original request, task DAG, write globs, interfaces, structured checks, budgets and scoped lead authority; collect per-version consent, freeze with an audited hash and amend in force. Ultraplan's `execution_ready` task block and archived sessions feed contracts; child contracts stay inside parent paths, budget and authority.
- Runner and workers: detached, recoverable scheduler; task-owned branches/worktrees; authenticated, keyless worker MCP servers with single-use rotating tokens; restricted Claude Code file tools, PreToolUse lease enforcement and startup attestation; explicitly opted-in Codex and external workers. Claims and conservative FIFO path leases coordinate work; submissions run checks on an isolated checkout of the submitted commit, and only that checked commit enters the serial integration merge queue. Resume adopts live workers or restarts interrupted ones with WIP/context; final validation and lead goal review gate completion. Never auto-merge or push to the base branch.
- Watchdog: budget ledger and model-price overrides, threshold warnings and hard-cap enforcement, lease/claim expiry, stalls, repeated-failure signatures, diff ping-pong, dependency deadlocks and per-driver/provider circuits. Idempotent process operations recover after crashes; transient failures and paused workers do not consume task attempts. Escalations route to two-turn micro-huddles, other private formats, the orchestrator or a scoped lead fallback; emergency pauses, owed resumes and concluded-huddle recovery survive restarts.
- Visibility: capability-protected, read-only loopback dashboard with task DAG, contract, diffs, checks, event stream, budget and human-action banners; optional GitHub issue/sub-issue and Projects sync with durable cursor/outbox, authenticated marker recovery, rate limits, redaction and needs-human labels, plus opt-in integration-branch PR publication. Progress tools provide focused views, weighted completion, rough ETA and bounded context. One-shot background watchers wake the host and are re-armed after each response.
- Tools: 15 additions bring the orchestrator from 22 → 37: `propose_contract`, `amend_contract`, `freeze_contract`, `execute`, `execution_status`, `control_execution`, `resolve_escalation`, `join_execution`, `read_blackboard`, `claim_task`, `lease`, `post_update`, `run_command`, `submit_work`, `escalate`. Worker servers expose the last seven, bound to startup identity; their orchestrator copies require execution id and agent token. Split the tool layer into groups with mode filtering, MCP annotations and shared argument validation; new tools reject unknown fields and worker responses deliver inbox directives/decisions.
- CLI: eight subcommands, `mcp`, `hook pre-tool-use`, `run`, `watch`, `status`, `verify`, `purge`, `help`; no arguments still starts the orchestrator stdio server. Execute preflights human confirmation, visibility, budget, sandbox, worker CLI and optional GitHub access; controls pause, resume, steer, abort and audit-confirmed terminal purge. Startup retention sweeps terminal runs and archived sessions after 30 days and audit months after 365 days by default, with independent keep-all settings.
- Security hardening: per-child environment allowlists (the trusted runner deliberately inherits its environment), guarded untrusted provider/webhook URLs and credential-origin binding, secret scrubbing before errors/logs/events/blobs, provider retry deadlines, private atomic/fsynced state, durable hash-chained event and monthly audit logs with pruning anchors. Docker command sandbox defaults to no network, non-root/read-only execution, protected git metadata and resource limits; install egress is explicitly allowlisted, and weaker local isolation needs opt-in and reports degradation. Harden host git, refuse submodules/nested repositories and escaping symlink chains, isolate prototype scripts/diagrams and protect localhost capability routes. Local meetings send prompts on stdin, use read-only tools, bounded process groups and the project workspace, and stop on server shutdown.
- Breaking and behavior changes: require Node ≥ 22. At-the-table session ids now use random suffixes and ended sessions are archived; active sessions still end on server restart. Agent file realpaths must remain within allowed agent directories; `ROUNDTABLE_AGENT_PATHS` adds roots. Concurrent turns fail fast with busy errors rather than queue; collaboration rounds are capped at 20. Add a validated three-task example contract, retain offline stdio and runner end-to-end smoke coverage, and reorganize the README into an index with mode, tool, CLI, configuration and provider guides.

## 0.4.0

- Prototype mode: `prototype: true` on `start_meeting`, `start_local_meeting` and `start_collaboration` lets agents show proposals. Works with standard and debate meetings and collaborate, debate and waffle-house collaborations; rejected with `mode: "conversation"`. With the flag unset nothing changes. Agents emit at most one `<prototype>` block per turn (1-10 files, hard cap 100 KB; the directive asks for under about 20 KB because a block cut off by the reply length cap is rejected) of kind `web` (a scaled-down page of just the proposed element), `code` (the artifact that would produce the proposal, such as SQL or Terraform; never executed), `diagram` (Mermaid) or `text` (draft 1). Agents are told to include `<demo>` walkthroughs for at least three user types or modalities when the proposal involves interaction; the parser does not enforce it. Assessors give `Verdict on Pn: APPROVE|REVISE|REJECT`; only the proposer decides `Decision on Pn: REVISE|SCRAP|SHORTLIST`; `revises="Pn"` creates `Pn v2`. A block that is not accepted (invalid, extra, cut off or unclosed, or arriving after close) is never shown raw: agents and the public see `[Prototype block not accepted: …]`.
- Lifecycle: prototypes are materialized into a sandbox, assessed by every other participant (the caller, through `say`/`say_local`, in meetings), and destroyed as soon as assessment completes. In collaborations, agents are told not to start a prototype or revision once fewer agent turns remain than assessment plus the proposer's decision needs. A TTL cap (`ROUNDTABLE_PROTOTYPE_TTL_MS`, default 30 min, at least 60000 ms), session completion or end, and server shutdown also destroy them and kill any headless Chrome. A sweep at startup (and on a root's first use) removes session directories whose `owner.json` names this host and a dead pid or that are older than 24 h, and directories without `owner.json` older than 1 h. Resolved prototypes appear in agent history, transcripts, end summaries and `from_session` input as one-line stubs; meeting status prompts go on the outgoing request only, never into the stored history.
- Board: one read-only localhost board per session at `http://127.0.0.1:<port>/<token>/` (a random capability token; every route lives under it). Auto-refreshing; web prototypes in sandboxed, opaque-origin desktop and mobile frames (so they need classic scripts, inline data and no localStorage, sessionStorage or cookies); diagrams rendered in the browser from a pinned Mermaid CDN version; code and drafts as text; destroyed prototypes return HTTP 410. Opt-in auto-open with `ROUNDTABLE_PROTOTYPE_OPEN=1`.
- Results and feedback hold: the start and `continue_collaboration` JSON results carry `prototypes` (`board_url`, `live` items with `label`, `title`, `kind`, `proposer`, `url` and `awaiting_verdicts_from`, `destroyed_this_call`, and a notice not to relay human feedback until the session ends); `say`/`say_local` end with a `Prototypes:` block; pause, nudge and transcript results carry none. `nudge_collaboration` is refused while a prototype is under assessment, and `continue_collaboration` resumes a paused prototype session. Agent turns and nudges in a prototype session are serialized so each turn keeps its message index. `end_*` adds Prototype outcomes and a Shortlist for the human (final source, diagram with mermaid.live link, or draft). `list_*` rows include `prototype` and `board_url`. The same persona twice is named `name` and `name #2` in prototype output. A private prototype `start_collaboration` whose auto-run fails is removed with its board and sandbox before the error is returned.
- Public prototype sessions: the localhost board is never posted, including in the end summary. The channel gets a Markdown reference per prototype (code capped at about 8 KB, mermaid.live link for diagrams, draft for text) and, when Chrome is available, desktop and mobile screenshots of web prototypes only, as ntfy attachments (PUT with a `Filename` header); the webhook publisher receives a text reference with attachment metadata and no bytes. Files are redacted before materialization. The public directive allows freshly written prototype code but never existing or private source. Screenshots are never sent to providers.
- Safety: the sandbox root (default under the OS temp directory) is refused inside a git work tree, as a symlink or when owned by another user, created with mode 0700 and `.gitignore`d. Code and IaC prototypes are never executed; web prototypes' JavaScript runs only in the sandboxed frame in your browser and, in public sessions, in a headless Chrome behind a deny-all proxy (the board), so it can reach only the prototype's own files. The board binds to `127.0.0.1`, checks the `Host` header, sends a restrictive Content-Security-Policy, forbids framing of the board and viewer, and accepts only GET and HEAD.
