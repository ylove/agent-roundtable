# Security controls mapping

This is an engineering mapping to SOC 2 Trust Services Criteria for agent-roundtable 1.0, not a SOC 2 report, certification or claim of operating effectiveness. Criterion descriptions below are paraphrased; applicability and evidence sufficiency require the operator's assessment. Read the [threat model](THREAT_MODEL.md) for boundary assumptions and residual risks.

**Administrative and organizational controls are out of scope and are the operator's responsibility.** These include personnel practices, access provisioning/revocation and periodic reviews, training, vendor assessment, endpoint/Docker/CLI patching, credential rotation, incident response, backup/restore, data classification, retention schedules, change approvals, branch/tag protection and monitoring evidence. Local code cannot supply these controls for a hosted or multi-user deployment.

File references are relative to the repository root. Tests demonstrate code behavior, not continuous operation. Design references cite `docs/design/heads-down.md`; worker drivers, runner/CLI, escalations and retention now have implementation and integration tests in this release tree. Platform sandbox and loopback-dependent tests still need an environment that permits them. Workflow actions are pinned by SHA and require maintainer verification. Registry audit, CodeQL upload and npm provenance must be verified in GitHub Actions with appropriate repository settings and credentials.
