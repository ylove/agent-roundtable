## 0.4.0

- Prototype mode: `prototype: true` on `start_meeting`, `start_local_meeting` and `start_collaboration` lets agents show proposals. Works with standard and debate meetings and collaborate, debate and waffle-house collaborations; rejected with `mode: "conversation"`. With the flag unset nothing changes. Agents emit at most one `<prototype>` block per turn (1-10 files, hard cap 100 KB; the directive asks for under about 20 KB because a block cut off by the reply length cap is rejected) of kind `web` (a scaled-down page of just the proposed element), `code` (the artifact that would produce the proposal, such as SQL or Terraform; never executed), `diagram` (Mermaid) or `text` (draft 1). Agents are told to include `<demo>` walkthroughs for at least three user types or modalities when the proposal involves interaction; the parser does not enforce it. Assessors give `Verdict on Pn: APPROVE|REVISE|REJECT`; only the proposer decides `Decision on Pn: REVISE|SCRAP|SHORTLIST`; `revises="Pn"` creates `Pn v2`. A block that is not accepted (invalid, extra, cut off or unclosed, or arriving after close) is never shown raw: agents and the public see `[Prototype block not accepted: …]`.
- Lifecycle: prototypes are materialized into a sandbox, assessed by every other participant (the caller, through `say`/`say_local`, in meetings), and destroyed as soon as assessment completes. In collaborations, agents are told not to start a prototype or revision once fewer agent turns remain than assessment plus the proposer's decision needs. A TTL cap (`ROUNDTABLE_PROTOTYPE_TTL_MS`, default 30 min, at least 60000 ms), session completion or end, and server shutdown also destroy them and kill any headless Chrome. A sweep at startup (and on a root's first use) removes session directories whose `owner.json` names this host and a dead pid or that are older than 24 h, and directories without `owner.json` older than 1 h. Resolved prototypes appear in agent history, transcripts, end summaries and `from_session` input as one-line stubs; meeting status prompts go on the outgoing request only, never into the stored history.
- Board: one read-only localhost board per session at `http://127.0.0.1:<port>/<token>/` (a random capability token; every route lives under it). Auto-refreshing; web prototypes in sandboxed, opaque-origin desktop and mobile frames (so they need classic scripts, inline data and no localStorage, sessionStorage or cookies); diagrams rendered in the browser from a pinned Mermaid CDN version; code and drafts as text; destroyed prototypes return HTTP 410. Opt-in auto-open with `ROUNDTABLE_PROTOTYPE_OPEN=1`.
- Results and feedback hold: the start and `continue_collaboration` JSON results carry `prototypes` (`board_url`, `live` items with `label`, `title`, `kind`, `proposer`, `url` and `awaiting_verdicts_from`, `destroyed_this_call`, and a notice not to relay human feedback until the session ends); `say`/`say_local` end with a `Prototypes:` block; pause, nudge and transcript results carry none. `nudge_collaboration` is refused while a prototype is under assessment, and `continue_collaboration` resumes a paused prototype session. Agent turns and nudges in a prototype session are serialized so each turn keeps its message index. `end_*` adds Prototype outcomes and a Shortlist for the human (final source, diagram with mermaid.live link, or draft). `list_*` rows include `prototype` and `board_url`. The same persona twice is named `name` and `name #2` in prototype output. A private prototype `start_collaboration` whose auto-run fails is removed with its board and sandbox before the error is returned.
- Public prototype sessions: the localhost board is never posted, including in the end summary. The channel gets a Markdown reference per prototype (code capped at about 8 KB, mermaid.live link for diagrams, draft for text) and, when Chrome is available, desktop and mobile screenshots of web prototypes only, as ntfy attachments (PUT with a `Filename` header); the webhook publisher receives a text reference with attachment metadata and no bytes. Files are redacted before materialization. The public directive allows freshly written prototype code but never existing or private source. Screenshots are never sent to providers.
- Safety: the sandbox root (default under the OS temp directory) is refused inside a git work tree, as a symlink or when owned by another user, created with mode 0700 and `.gitignore`d. Code and IaC prototypes are never executed; web prototypes' JavaScript runs only in the sandboxed frame in your browser and, in public sessions, in a headless Chrome behind a deny-all proxy (the board), so it can reach only the prototype's own files. The board binds to `127.0.0.1`, checks the `Host` header, sends a restrictive Content-Security-Policy, forbids framing of the board and viewer, and accepts only GET and HEAD.
- `debug_env` reports a `prototypes` block (`dir`, `chrome`, `screenshots`, `open_browser`, `ttl_ms`, `active_boards`) and the startup banner gains a prototype line. New environment variables: `ROUNDTABLE_PROTOTYPE_DIR`, `ROUNDTABLE_PROTOTYPE_TTL_MS`, `ROUNDTABLE_PROTOTYPE_OPEN`, `ROUNDTABLE_CHROME_PATH`, `ROUNDTABLE_PROTOTYPE_SCREENSHOTS`. Tool count stays 22. No new dependencies. Package version is now 0.4.0.

## 0.3.0

- Ultraplan: the orchestrator writes plans shaped by specialist input, independent version reviews and final sign-offs; an optional planner persona runs the entire loop in one call. Final documents include input, sign-offs and revision history, with optional public mirroring. `submit_plan` can omit `plan` to review or sign off the latest version as-is without adding a version; stopped planner runs return unreviewed versions with `phase: "plan"` and earlier reviews in `previousReviews` when available, for recovery with `submit_plan` or `end_ultraplan`.
- Conversation mode: informal agent chat with an optional theme, short turns and truthfulness guidance. Private sessions can draw on workspace, agent-memory and local activity excerpts; `grounding: false` disables this, and public conversations never receive grounding or open on the founder angle, and their directive does not ask about the founder or whoever agents report to.
- Agent creation and refinement: specialists contribute expertise and skills, an architect drafts the definition, and participants review it. Supports live-session context, dry-run previews, optional task delegation, collision-safe creation, refinement backups and restricted generated frontmatter.
- Frontmatter is read the way Claude Code reads it, with one quoting/tab recovery pass and no line fallback. Refinement preserves exactly Claude-visible keys and refuses files Claude Code cannot parse or whose frontmatter contains `---` inside a value. Generated descriptions normalize triple hyphens, and serialization checks the Claude-compatible round trip. Per-target improve locks prevent concurrent runs. Edits, renames or deletions during a run produce `.proposed-` files with the original mode; replacements are atomic and keep the original mode after a `.bak-` backup.
- Generated tools fail closed: no allowlist matches or the wrong type triggers one architect retry; omitted tools warn that the agent inherits all tools.
- Public workshops post contributions, reviews and redacted definition summaries without system prompts, skill instructions or descriptions derived from instructions; copied private passages in summary fields are withheld. Public improve prompts omit recent activity and ask participants and the architect to point to passages rather than reproduce them; private contributor prompts include local activity topics and outcomes.
- Personas inline skills from frontmatter. Lookup follows personal, project, then configured skills precedence; found skills are reused without overwrites or shadowing. Creation searches the destination project's skills even with a separate configured directory, and writes new skills to the configured directory. Refinement writes beside a target in its project's `.claude/skills` when it sits in `.claude/agents`, provided neither Claude directory is a symlink and the skills realpath stays inside the project; otherwise it falls back to the configured directory with a warning. Results report file realpaths. Completed sessions record best-effort local activity, used for conversation grounding and refinement.
- Five new tools bring the total to 22 and validate argument types before routing or engine calls. `debug_env` and startup diagnostics report skills/workspace directories and activity settings; diagnostics also report parallel turn limits and active ultraplans. Package version is now 0.3.0.
- New environment variables: `ROUNDTABLE_SKILLS_DIR`, `ROUNDTABLE_WORKSPACE_DIR`, `ROUNDTABLE_ACTIVITY_LOG`, `ROUNDTABLE_PARALLEL_TURNS`.

## 0.2.0

- Public sessions: `public: true` on `start_meeting`, `start_local_meeting` and `start_collaboration` mirrors the session live to a public channel (ntfy by default, or a webhook), saves a Markdown transcript locally when the session ends, and reports the URL, saved path and delivery counts in the `end_*` results. Includes redaction, chunking, rate-limit handling, and a privacy notice added to every agent's system prompt. Publishing never blocks or fails a session. The `context` argument is never posted.
- New modes: `debate` for meetings, local meetings and collaborations (with `debate_focus`), and `waffle-house` for collaborations (one defender, the rest attackers; always ends on the defender).
- Fix: round counting now ignores orchestrator nudges, so a nudge no longer brings the end of a collaboration forward.
- `list_*` results include `mode` and `public`; `debug_env` reports the publisher settings (presence only for secrets).
- New environment variables: `ROUNDTABLE_PUBLISHER`, `ROUNDTABLE_NTFY_URL`, `ROUNDTABLE_NTFY_TOKEN`, `ROUNDTABLE_NTFY_USER`, `ROUNDTABLE_NTFY_PASSWORD`, `ROUNDTABLE_WEBHOOK_URL`, `ROUNDTABLE_WEBHOOK_VIEW_URL`, `ROUNDTABLE_WEBHOOK_AUTH_HEADER`, `ROUNDTABLE_PUBLIC_TOPIC_PREFIX`, `ROUNDTABLE_TRANSCRIPTS_DIR`, `ROUNDTABLE_PUBLISH_FLUSH_TIMEOUT_MS`.
- README: `debug_env` no longer described as showing a key prefix (it reports presence only).
