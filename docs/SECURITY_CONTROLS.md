# Security controls mapping

This is an engineering mapping to SOC 2 Trust Services Criteria for agent-roundtable 1.0, not a SOC 2 report, certification or claim of operating effectiveness. Criterion descriptions below are paraphrased; applicability and evidence sufficiency require the operator's assessment. Read the [threat model](THREAT_MODEL.md) for boundary assumptions and residual risks.

**Administrative and organizational controls are out of scope and are the operator's responsibility.** These include personnel practices, access provisioning/revocation and periodic reviews, training, vendor assessment, endpoint/Docker/CLI patching, credential rotation, incident response, backup/restore, data classification, retention schedules, change approvals, branch/tag protection and monitoring evidence. Local code cannot supply these controls for a hosted or multi-user deployment.

File references are relative to the repository root. Tests demonstrate code behavior, not continuous operation. Design references cite `docs/design/heads-down.md`; worker drivers, runner/CLI, escalations and retention now have implementation and integration tests in this release tree. Platform sandbox and loopback-dependent tests still need an environment that permits them. Workflow actions are pinned by SHA and require maintainer verification. Registry audit, CodeQL upload and npm provenance must be verified in GitHub Actions with appropriate repository settings and credentials.

Local meetings use restricted mode, explicit hook-disabled settings, disabled slash commands/Chrome and strict MCP config, with required-flag preflight cached per CLI path (`src/sessions/local-meetings.ts`; `sessions-modes.test.mjs`). Project `CLAUDE.md` context may be omitted; the trusted CLI must honor these flags, and cwd remains no OS read boundary.

The agents library (`src/library/server.ts`) uses `SecureServer`'s loopback bind,
Host validation, capability token and response headers. Its only mutating route,
`POST /import`, checks `sameOriginProblem`, a per-start `X-Roundtable-Action`
nonce delivered in a page meta tag, and `Content-Type: application/json` before
reading content. It accepts at most 20 import requests per minute, 50 files per
request and 2 MiB of JSON with a hard streaming cap. Each persona is limited to
128 KiB. Imports refuse path filenames, empty/reserved slugs, ambiguous metadata
and unknown JSON keys; files are created exclusively at mode 0600 in a library
created at mode 0700. Folder imports skip symlinks and stop at 200 files. A symlinked
library is not an approved loader root, and realpath containment still applies.
The page has no inline scripts or styles, limits connections to itself, and renders
untrusted text through `textContent`. Imported instructions remain untrusted for
later use. Evidence: `test/unit/library-import.test.mjs`, `library-lookup.test.mjs`,
`library-server.test.mjs` and `library-cli.test.mjs`.

## Credentials broker and worker connectors

- User configuration stores strictly parsed `secret://` references. Owner and writable-mode checks apply before reading it. Invalid secret entries warn once by name and are ignored. No MCP tool resolves or returns credentials.
- The broker caches only in memory and registers every resolved value with the call-time scrub literals, including short values and ordinary env names. Trusted runner, relay and roundtable worker-server processes carry the same redactions for logs, events, blackboard writes, artifacts, notifications and archives.
- Keychain and 1Password backends use absolute executable lookup, `execFile`/`execFileSync` without a shell, a minimal `secret-cli` environment, capped output and fixed timeouts. Stderr never leaves the backend. Startup has a 20-second total budget; failures leave keys unset and do not fall back to plaintext for that key.
- Connector names are frozen contract data. Propose/freeze validate local names; execute rejects missing connectors. Changes are run-wide for consent. Codex workers refuse connectors. Claude allowlists and attestation accept only the contract servers.
- Each connector receives BASE plus configured variables through a trusted environment-filtering stdio launcher. Its resolved MCP config is 0600 in a private 0700 worker directory outside task worktrees and sandbox mounts. The relay removes it on exit; the runner removes it on reap/recovery or an interrupted launch. The trusted worker server receives scrub literals in this same private file. A hard crash can leave the file until recovery or purge.
- Connectors and credential CLI binaries are trusted host processes. Connector tools may change external state; they are outside the command sandbox. Exact scrubbing cannot contain a malicious connector or guarantee redaction of transformed credentials.
