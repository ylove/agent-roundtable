# Security audit, October 2026

Date: 2026-10-20. Tracking issue: [#167](https://github.com/ylove/agent-roundtable/issues/167).

## Scope and method

The audit had two parts:

- A dependency and CVE review of the lockfile and the published package.
- A whole-repository adversarial review of source, configuration and documentation, with independent reviews of the new 2.0 surfaces: the CLI, the room, the duel mode and meeting focus.

This page lists the controls now in place as a result. Each item links to the pull request that introduced it, and each has regression tests in the repository.

To report a vulnerability, follow [SECURITY.md](../../SECURITY.md). For the design-level view, see the [threat model](../THREAT_MODEL.md) and the [controls mapping](../SECURITY_CONTROLS.md).

## Results

### Dependencies

- The lockfile resolves the transitive `hono` dependency to a patched release, and `npm audit` reports 0 vulnerabilities. ([#170](https://github.com/ylove/agent-roundtable/pull/170))

### Process execution

- Executable lookup returns absolute canonical paths. ([#170](https://github.com/ylove/agent-roundtable/pull/170))
- The runner's child process environment is built from an allowlist. Proxy and CA-certificate settings are kept so that corporate networks keep working. ([#170](https://github.com/ylove/agent-roundtable/pull/170))
- Duel sandboxes are cleaned up when a duel finishes. ([#173](https://github.com/ylove/agent-roundtable/pull/173))

### Filesystem containment

- Workspace grounding and agent roots are contained to their configured directories. ([#170](https://github.com/ylove/agent-roundtable/pull/170))
- Duel archives are written atomically with private permissions and are pruned under the session retention policy. ([#173](https://github.com/ylove/agent-roundtable/pull/173))
- Configuration and env files must be owner-only. ([#173](https://github.com/ylove/agent-roundtable/pull/173))
- The duel meeting-focus reader opens archives without following symlinks, requires a regular file, and enforces a size limit. ([#184](https://github.com/ylove/agent-roundtable/pull/184))

### Secret handling

- Scrubbers run in linear time. ([#170](https://github.com/ylove/agent-roundtable/pull/170))
- Structured blobs have credentials redacted while identifier maps and persona references are preserved. ([#170](https://github.com/ylove/agent-roundtable/pull/170))
- Additional credential patterns are recognized. ([#170](https://github.com/ylove/agent-roundtable/pull/170))
- Duel events and archives are scrubbed before they are written. ([#173](https://github.com/ylove/agent-roundtable/pull/173))
- Duel artifact content is scrubbed with credential-shaped rules only (vendor key formats, PEM blocks, JWTs, bearer and basic headers, URL credentials) plus exact configured values, so source code stays intact. ([#187](https://github.com/ylove/agent-roundtable/pull/187))
- The OpenAI-compatible URL and key are imported as a pair. ([#173](https://github.com/ylove/agent-roundtable/pull/173))
- `.env.example` documents the webhook header setting. ([#170](https://github.com/ylove/agent-roundtable/pull/170))

### Network and input handling

- Publisher inputs are size-capped. ([#170](https://github.com/ylove/agent-roundtable/pull/170))
- Relay JSON parsing has a depth bound. ([#170](https://github.com/ylove/agent-roundtable/pull/170))
- Provider responses are size-capped. ([#170](https://github.com/ylove/agent-roundtable/pull/170))
- Requests to local model endpoints do not follow redirects. ([#170](https://github.com/ylove/agent-roundtable/pull/170))
- Duel replay size and timers are capped. ([#173](https://github.com/ylove/agent-roundtable/pull/173))

### 2.0 surfaces

CLI and terminal:

- Terminal output and NDJSON escape control characters. ([#173](https://github.com/ylove/agent-roundtable/pull/173))
- Seat model ids are validated. ([#173](https://github.com/ylove/agent-roundtable/pull/173))
- `execute` refuses to start when the execution provider's key is rejected, and names the provider and setting to fix. ([#194](https://github.com/ylove/agent-roundtable/pull/194))

Duel and room:

- Judge listings are fenced with per-run nonces and labelled as untrusted. ([#180](https://github.com/ylove/agent-roundtable/pull/180))
- Non-web artifacts are served as plain text with a sandbox Content-Security-Policy and are never executed. ([#180](https://github.com/ylove/agent-roundtable/pull/180))
- `start_duel` validates its input: team and judge counts, and duplicate personas. ([#180](https://github.com/ylove/agent-roundtable/pull/180))

Meetings:

- A duel used as a meeting focus is summarized into a scrubbed, size-capped brief with per-session nonce fences, labelled untrusted. Bad, traversal, symlinked or missing ids are rejected before any provider call. ([#184](https://github.com/ylove/agent-roundtable/pull/184))
